# M4-W2: curious controllers in the locked-rooms world (grok, Kaggle CPU)

Read `/root/pdp/CLAUDE.md` first, then `results/w2_headroom/RESULTS.md` (including its Verdict), `w2_world.py` and
`w2_headroom.py` (the world, the learner, the probe and the kernel layout), and `h28_progress_replay.py` (how
progress was measured before).

## Context
W2-0 showed that the locked-rooms world rewards acting. rand8 never gets past room 2. The oracle knows every room.
rand6, which never presses reset or the TV, drifts to room 8 and stays there, because room 8 has no exit. With each
room's probe capped at 4 bits, rand6 − oracle is 1.57 / 0.50 / 0.76 bits per observation. That smaller gap is the room
left for a controller that plans.

This run closes the loop for the first time. A controller picks every action from what the learner has gained so far,
and the learner learns from what the controller chose. Principles served: reward compression progress (3) and act to
maximise it (4).

## Shared parts (identical to W2-0 unless stated)
- **World, tokens, learner, replay and probe** are exactly as in `w2_world.py` and `w2_headroom.py`: GRU 32/128,
  Adam lr 1e-3, clip 1.0, 64-token chunks (32 steps), TBPTT 64, hidden state carried across chunks, prequential
  scoring before each live step, replay of 8 windows from even positions after each live step, learner SEED 0,
  T = 60,000 steps.
- Import from those two files. Do not edit them. Put the new code in `m4w2.py`.
- **Closed loop.** The life can no longer be rolled out in advance. Process it chunk by chunk:
  1. **Act.** Choose the chunk's 32 actions one at a time, stepping the world after each. Use the controller's
     values as they stood at the start of the chunk; values are frozen inside a chunk.
  2. **Score.** Run the learner on the chunk's 64 tokens with the carried hidden state. The observation bits are
     `bits_before[i]` for step i of the chunk. This is the prequential score.
  3. **Learn.** Take the live step, then the replay step, exactly as W2-0 does.
  4. **Re-score.** Run the chunk again under no_grad with the *same* initial hidden state used in 2. Call these
     `bits_after[i]`. One extra forward per chunk.
  5. **Update the controller.** Feed it the chunk's transitions in order (below). Then carry the hidden state from
     step 2, as W2-0 does.
- **Controller state** = the room the agent is in before the action, an integer 0..8. The lock state is hidden.
- **Tabular Q-learning** for the three `_q` arms: Q is 9 × 8, zero-initialised. Act ε-greedy: with ε = 0.1 pick
  uniformly from all 8 actions, otherwise argmax Q[room] with ties broken uniformly. For each transition (room, a, r,
  room′) in order, update Q[room, a] += α (r + γ max Q[room′] − Q[room, a]), with α = 0.1 and γ = 0.9. Seed the
  controller rng with `default_rng(7_000 + world_seed)`.
- **Rewards** for step i, all in bits:
  - `prog_q`: r = bits_before[i] − bits_after[i]. This is compression progress on that step's observation, caused by
    this chunk's update. Use the raw value. It can be negative. Do not clip it.
  - `err_q`: r = bits_before[i]. This is surprise, the "noisy TV" trap.
  - `count_q`: r = 1 / sqrt(n(room, a)), where n is the number of times (room, a) has been taken so far, including
    this step. This is count novelty, the standard exploration baseline.
- **Fixed arms** for reference: `rand6`, `rand8` and `oracle`, with the same policies and rngs as W2-0, run through
  the same closed-loop code. Their bits must match W2-0 to 1e-6 on world seed 0, which is the smoke check below.

## Arms and seeds
- Six arms: `rand6`, `rand8`, `oracle`, `prog_q`, `err_q`, `count_q`.
- **World seeds 3, 4, 5, 6, 7, 8.** These are held out. Seeds 0–2 were used to set this design and are not scored.
- That makes 36 lives. Use three private CPU kernels, `ezzzzzx/m4w2-a`, `-b` and `-c`, with two world seeds each:
  (3, 4), (5, 6), (7, 8). Each has `"is_private": true`, `"enable_gpu": false` and `"enable_internet": false`. The code
  goes up as private dataset `ezzzzzx/pdp-code-m4w2`. Do not use the GPU.

## Metrics, per life
- **PROBE_cap** (the headline): the mean over rooms k = 0..8 of min(probe_k, 4.0), at T. Also report the raw PROBE and
  all 9 probe_k at T/4, T/2 and T, as W2-0 does.
- TV probe at T.
- Whole-life prequential bits per observation, and per quarter.
- Time-in-room histogram, deepest room, and the first step it was reached.
- **Action shares:** the fraction of steps on the TV, on reset, and on each manipulation.
- Resets per 1,000 steps in each quarter.
- For the `_q` arms: the final Q table, and the mean reward per (room, a) over the last quarter.
- Wall seconds.

## Smoke test (VPS CPU, before any kernel)
1. **Equivalence:** on world seed 0 with T = 640, the closed-loop code under `rand6`, `rand8` and `oracle` (oracle
   block size 32) gives the same token sha256 and the same total bits as W2-0's `run_life` with the same settings,
   to 1e-6. Report both.
2. Each `_q` arm on world seed 0 with T = 640 gives finite bits, finite Q values and a valid action share. Print
   their action shares.
3. **Re-score check:** on one chunk, bits_after computed with the learner frozen and no update equals bits_before to
   1e-6.
If any check fails, stop and report. Do not push kernels.

## Outputs
`results/m4w2/RESULTS.md` and `results/m4w2/results.json`, with numbers only and no verdict:
- a table per arm: PROBE_cap mean ± std (ddof = 0) over seeds 3–8, and per seed;
- the gaps per seed, with mean ± std: rand6 − prog_q, count_q − prog_q, err_q − prog_q and prog_q − oracle, all on
  PROBE_cap;
- the same table with raw PROBE;
- TV share and reset share per arm (mean over seeds);
- deepest room and time in room 8 per arm;
- kernel ids, elapsed seconds and smoke-test numbers.

## Pre-registered bars (orchestrator scores; do not change)
1. **Curiosity works in a depth world:** mean over seeds 3–8 of (rand6 − prog_q) on PROBE_cap is ≥ 0.25 bits per
   observation, and prog_q beats rand6 on at least 4 of the 6 seeds.
2. **Progress beats novelty:** mean (count_q − prog_q) on PROBE_cap is ≥ 0.10.
3. **The noisy TV, a prediction:** err_q puts ≥ 30% of its steps on the TV, and prog_q puts ≤ 5% there.

Kill rule: if prog_q is worse than rand6 on mean PROBE_cap, the progress controller as built fails in a depth world.
The verdict then names the mechanism from the Q tables and action shares.
