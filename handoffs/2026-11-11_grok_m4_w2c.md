# M4-W2c: a curious controller with memory (grok, Kaggle CPU)

Read `/root/pdp/CLAUDE.md` first, then `results/m4w2b/RESULTS.md` (including its Verdict), `m4w2b.py`, `m4w2.py`,
`w2_world.py` and `w2_headroom.py`.

## Context
M4-W2b fixed the noise leak: visit-to-visit learning progress watched the TV only 2.2% of the time. It still lost to
rand6 by 2.08 bits on PROBE_cap. The controller's state was the room alone, and the lock is a hidden 3-step sequence.
Once a room was learned, greedy Q repeated one action and never typed a key. The reward waiting in unvisited rooms
could not flow back through a sequence the state could not represent.

The pre-registered next step is a controller with memory. With the last two actions in the state, the lock state is
(almost) a function of the controller state. Tabular Q-learning can then learn each key and carry the optimistic value
of unvisited rooms back to the door. Principles served: reward compression progress (3) and act to maximise it (4).

## What changes from `m4w2b.py` (everything else identical)
Create `m4w2c.py`. Import from `m4w2b.py`, `m4w2.py`, `w2_world.py` and `w2_headroom.py`, and do not edit them.

1. **Memory state for the `_mem` arms:** state = (room, p1, p2). Here p1 is the previous action and p2 the one
   before. Each takes values 0..8, where 8 means "none": the life has just started, or the room changed since that
   action was taken. Whenever the room changes, including by reset, set both p1 and p2 to 8. That gives
   9 × 9 × 9 = 729 states, and Q is 729 × 8, zero-initialised.
   - Note: a TV press leaves the lock state unchanged, so a TV press between digits makes the state non-Markov.
     Accept that.
2. **Q-learning** as before: α = 0.1, γ = 0.9, ε = 0.1 over manipulations {0..5} only, greedy over all 8 actions with
   uniform tie-breaking, and controller rng `default_rng(7_000 + world_seed)`.
3. **Rewards:**
   - `lp_mem`: M4-W2b's `prog_lp` reward exactly. Context (room before action, action), K = 16, reward 1.0 for the
     first 2K visits of a context, prequential bits only. Only the controller state changes.
   - `count_mem`: r = 1 / sqrt(n(state, action)), counting over the 729 × 8 state-action pairs, including this step.
   - `lp_room`: M4-W2b's `prog_lp` exactly, with room-only state. This is the reference on the new seeds.

## Arms and seeds
- Four arms: `rand6`, `lp_mem`, `count_mem` and `lp_room`.
- **World seeds 15, 16, 17, 18, 19, 20.** These are fresh and held out. Seeds 3–14 have been used.
- That makes 24 lives. Use three private CPU kernels, `ezzzzzx/m4w2c-a`, `-b` and `-c`, with seeds (15, 16),
  (17, 18) and (19, 20). Each has `"is_private": true`, `"enable_gpu": false` and `"enable_internet": false`. The code
  goes up as private dataset `ezzzzzx/pdp-code-m4w2c`. No GPU.

## Smoke test (VPS CPU, before any kernel)
1. **Equivalence:** with world seed 0 and T = 640, `rand6` and `lp_room` through `m4w2c.py` match M4-W2b's `rand6` and
   `prog_lp` exactly: same token sha256, and total bits to 1e-6.
2. **State check:** on a scripted sequence from reset, the state after each step is as expected. Play key_0[0],
   key_0[1], key_0[2] (entering room 1), then one manipulation, then the TV, then reset. Expect (0,8,8) →
   (0,k0,8) → (0,k1,k0) → (1,8,8) → (1,a,8) → (1,6,a) → (0,8,8), where k0 and k1 are the first two key digits. Print
   it.
3. **Capability check (no learner):** in world seed 0, give the Q-learner a fixed reward of +1 on every step that
   enters a room it has never entered before, and 0 otherwise, with the memory state and ε as above, for
   T = 20,000 steps. Report the deepest room reached and the first step it was reached. This checks that the memory
   state can learn keys at all. Report the number only; it is not a bar.
4. Each arm with T = 640 gives finite bits and finite Q.
If check 1 or 2 fails, stop and report. Do not push kernels.

## Outputs
`results/m4w2c/RESULTS.md` and `results/m4w2c/results.json`, with numbers only and no verdict. They use the same
fields as M4-W2b, plus:
- the gaps per seed, with mean ± std (ddof = 0), on PROBE_cap: rand6 − lp_mem, count_mem − lp_mem and
  lp_room − lp_mem;
- the deepest room and the first step it was reached; time in room per quarter; resets per 1,000 steps per quarter;
- the capability-check result from the smoke test.

## Pre-registered bars (orchestrator scores; do not change)
For scale, rand6 − oracle on PROBE_cap was 0.50 ± 0.14 (seeds 3–8). rand6 alone was 0.97 ± 0.24 on seeds 9–14.
1. **Curiosity beats the no-reset random walk:** mean over seeds 15–20 of (rand6 − lp_mem) on PROBE_cap is ≥ 0.25, and
   lp_mem beats rand6 on at least 4 of the 6 seeds.
2. **Progress beats novelty:** mean (count_mem − lp_mem) ≥ 0.10.
3. **Memory is what was missing:** mean (lp_room − lp_mem) ≥ 1.0.
Report only: TV share of lp_mem, which should stay ≤ 0.10.

Kill rule: if bar 3 fails, memory was not the bottleneck. The tabular controller line on W2 then stops, and the next
design moves to a model-based planner: plan with the learner's own predictions. If bar 3 holds but bar 1 fails, the
controller can open locks, but its progress reward does not beat a random walk on world knowledge. That gets recorded
as the finding.
