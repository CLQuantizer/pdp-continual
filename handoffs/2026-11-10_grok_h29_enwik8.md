## Why
Our cortex has only been measured on a toy world. enwik8 (first 10^8 bytes of English Wikipedia, Hutter Prize) has
published compressor numbers: a ruler. This is passive (no curiosity): how good is our learner as a compressor?

## Data
Download http://mattmahoney.net/dc/enwik8.zip on this VPS into `data/enwik8/` (gitignored), check the unzipped size is
100,000,000 bytes and report its sha256. Upload as a **private** Kaggle dataset `ezzzzzx/enwik8` (data only).

## Learner (one online pass, prequential, byte alphabet 256)
- GRU, embedding 64, hidden 1024, 1 layer, Adam lr 1e-3 (try 3e-3 on the first 1 MB only, pick the better, say which),
  grad clip 1.0, on the T4 (`enable_gpu: true`).
- Stream in chunks of 128 bytes. For each chunk: record −log2 p of every byte **before** any update (carry the GRU state
  across chunks), then one Adam step on that chunk (truncated BPTT 128), then **one replay step**: batch 32 segments of
  128 bytes drawn uniformly from all bytes seen so far (zero state). This is H27b's best dose rule, scaled.
- Code length = sum of −log2 p over all bytes (that is the prequential code; the decoder is the same program).
- Also report a no-replay variant on the first 2 MB, to show what replay buys at this scale.

## Baselines on exactly the same E10M bytes (run on the VPS, CPU)
`xz -9e -T1`, `zstd --ultra -22 --long=27`, python `bz2` level 9, python `lzma` preset 9|EXTREME, and PPMd via
`.venv/bin/pip install pyppmd` (variant H, order 6 and order 16, max memory 1 GB if allowed). Bits/byte = 8 × size / 1e7.
Published full-enwik8 references to quote (Mahoney's LTCB): xz 1.976, ppmd J1 1.711, cmix v21 1.170 bits/byte (note
these are full-file numbers; E10M numbers will be higher because less data has been seen).
