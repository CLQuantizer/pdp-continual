# H34c: grow the stack like a developing cortex (grok: implement, smoke, run on Kaggle CPU)

Read `/root/pdp/CLAUDE.md`, `handoffs/2026-11-18_codex_h34b_plain_depth.md` (with its amendment) and `h34b_plain_depth.py` (codex's code; another grok
job is running its kernels now; do not edit it or its folders).

## Why
In the brain, lower sensory areas mature and close their critical periods before higher ones: depth is trained bottom-up over development. Our working
local stack trains all layers at once. If upper layers learn on inputs that are still changing, their learning is partly wasted. H34c asks whether growing
the stack, adding a layer only once the one below has settled, is a better depth recipe.

## Setup
Exactly H34b's `plain` arm after its amendment (first 180,000 bytes of enwik8, tail scored on 40,000–180,000, N = 128 per layer, stateless input
normalisation, own loss per layer, learned GeoMixer, zero-init readouts), seeds 0 and 1. Import from `h34b_plain_depth.py`; do not edit it.

## Arms
- `plain_4`: H34b's plain_4 (rerun here so the comparison shares code and machine).
- `grow_4_sched`: start with 1 layer; add layer k+1 (zero-init readout, so it changes nothing when added) at bytes 20,000, 40,000, 60,000. Layers keep learning
  after the next one is added.
- `grow_4_settle`: add layer k+1 when layer k's own bits/byte, averaged over the last 4,096 bytes, has improved by less than 0.5% over the previous 4,096-byte
  window, checked every 4,096 bytes, at most 4 layers. Log the byte at which each layer was added.
- `grow_4_freeze`: as `grow_4_sched`, but a layer stops learning when the next one is added (greedy layer-wise; its readout still feeds the mixer).
A layer added mid-stream starts with its recurrent state at zero. The mixer gets a new weight, initialised to 1, when a layer is added.

enwik8 dataset as H34a. Keep the account's running kernels ≤ 5 (other jobs run now; wait for free slots). At most 90 minutes per kernel.

## Smoke (VPS, one thread)
(1) `plain_4` reproduces H34b's plain_4 bits over its first 8,192 bytes to 1e-9; (2) adding a layer leaves the stack's prediction unchanged at that byte
(identity, to 1e-9); (3) `grow_4_freeze`'s frozen layers' parameters are bit-identical after their freeze point; (4) prequential prefix check; (5) wall estimates.

## Outputs

mixer weights, 20 KB slice table.
